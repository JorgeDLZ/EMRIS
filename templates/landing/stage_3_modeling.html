Model engineering

Which algorithms were compared for each component, how they are configured and how their settings were chosen.

Algorithms compared
  • Impact estimator: logistic regression and gradient boosting (scikit-learn HistGradientBoostingClassifier), against a baseline that predicts the high-impact rate of the same event type and municipality (falling back to type and department, then to type).
  • Emergency profiles: K-means with 3 to 8 groups.
  • Similar emergencies: k-nearest neighbors with and without the impact variables, against random neighbors of the same event type.
  • Municipal risk: hierarchical agglomerative clustering (Ward) with 3 to 5 levels.
Why these algorithms
  • Logistic regression works well with many one-hot categories and few rows per category, and its coefficients explain each estimate (the main factors shown on the emergency). Gradient boosting was included because it can capture interactions between type, place and month.
  • K-means gives one centroid per group, so each profile can be named after the impact variables that stand out in it.
  • k-nearest neighbors returns real past emergencies, so every suggested action can be traced back to the cases it comes from.
  • Ward clustering suits a few hundred municipalities, is deterministic and can be read on a dendrogram; since it cannot classify new points, the stored model is the municipality-to-level table of each version.
Features, parameters and configuration
  • Impact estimator: event type, department, municipality and cyclic month. Logistic regression with C = 1, balanced class weights and up to 2,000 iterations; gradient boosting with learning rate 0.1, no depth limit and balanced class weights. The decision threshold maximises F1 on September (0.499 for the selected model).
  • Emergency profiles: the nine impact variables after log1p and standardisation; K-means with 10 initialisations; K chosen by silhouette. Emergencies with no recorded impact are labelled “No recorded impact” instead of being clustered.
  • Similar emergencies: k = 5; event type weighs 5 and department, municipality, month and impact weigh 1 each. An action is suggested when at least 2 of the 5 neighbors had it.
  • Municipal risk: municipalities with at least 3 emergencies; K chosen by silhouette between 3 and 5; levels numbered by a severity score, from level 1 (lowest) upward.
Validation and hyperparameter tuning

The candidate is chosen on the September validation month (PR-AUC 0.46 for logistic regression against 0.41 for gradient boosting) and never on the test months. Gradient boosting would only be preferred if it beat logistic regression by more than 0.02 PR-AUC.

Experiments and domain knowledge
  • No leakage: the impact estimator uses only what is known when an emergency is reported; a test checks that no impact variable reaches it.
  • Shallow earthquakes only: municipal risk counts earthquakes shallower than 70 km, because the deep Bucaramanga nest under Los Santos and Zapatoca (Santander) holds 5,703 of the 14,332 events and rarely causes damage.
  • Insufficient history: municipalities with fewer than 3 emergencies get “Insufficient history” instead of an unreliable level.
  • Event type first: in similarity the event type weighs 5, because an emergency of another type is rarely a useful example, whatever its place or month.
  • Label sensitivity: recomputing the 90th-percentile thresholds of the target on the training months only changes 22 of the 6,505 labels (notebook 06).
  • Experiment record: six notebooks — 01 exploration, 02 impact estimator, 03 emergency profiles, 04 similar emergencies, 05 municipal risk and 06 cross-validation.
